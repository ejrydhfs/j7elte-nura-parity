# USB parity — j7elte (EHCI_S5P, OHCI_EXYNOS, OTGD, DWC USB2 PHY, USB switch)

**Verdict: PARITY (P1–P4 pass). No kernel patch required. No device-tree deltas found.**

Scope: `CONFIG_USB_EHCI_S5P` (`drivers/usb/host/ehci-s5p.c`),
`CONFIG_USB_OHCI_EXYNOS` (`drivers/usb/host/ohci-exynos.c`, included by
`ohci-hcd.c`), `CONFIG_USB_S3C_OTGD` (`drivers/usb/gadget/s3c_udc_otg*.c`),
`CONFIG_SAMSUNG_DWC_USB2PHY` (`drivers/usb/phy/phy-samsung-dwc-usb2.c`) +
`CONFIG_SAMSUNG_USBPHY` helper (`drivers/usb/phy/phy-samsung-usb.c`),
`CONFIG_USB_EXYNOS_SWITCH` (`drivers/usb/misc/exynos-usb-switch.c`), and the
Samsung USB notify layer that binds the `samsung,exynos_udc` node
(`drivers/usb/notify/usb_notifier.c`). Note the 3.10 tree has **no `drivers/phy/`**;
all PHY drivers live under `drivers/usb/phy/`.

Reference points:
- ROM: `boot_out/symbols.txt` (55,634 kallsyms names), `boot_out/dtbs/000_800.dts`
  (also `001_19800.dts`, `002_32800.dts` — same USB nodes, only phandle numbers differ), `system.raw`
  (`/etc/firmware`, `/vendor/firmware`).
- Nura tree: `android_kernel_samsung_universal7580-…-2a746c1…/` at git `b5e363a`
  (working tree clean on `drivers/usb`), config `config-nura-j7elte`, DT
  `arch/arm64/boot/dts/exynos7580.dtsi` + `exynos7580-j7elte_rev06.dts`.
- Static verification only: no kernel build was performed. An
  `aarch64-linux-gnu-gcc` exists on the host, but the 3.10 downstream tree is not
  expected to build with it, so symbol/DT/config checks are static.

## P2 — Device tree: PASS, zero deltas

All six ROM nodes were compared property-by-property against the Nura j7elte DT
(flat ROM `000_800.dts`, Nura `exynos7580.dtsi:832-889` +
`exynos7580-j7elte_rev06.dts:1134`). After ignoring the legacy duplicate
`linux,phandle` property emitted by the ROM's dtc, **every node and property is
identical**:

| `usb@13510000` (`samsung,exynos7580-ehci`) | `:3632` | `:843` | compatible, reg, interrupts `<0 239 0>`, 7 clocks (`0x12c,0x12f-0x134`), 7 names, `usb-phy`, `status="ok"` | none |

Phandle numbers (`usb2_phy`=0x50, `ehci`=0x51, `ohci`=0x52) are board-build
artefacts and are ignored per contract; the targets are the same nodes.
Consumers match the properties: `usb-phy` via
`devm_usb_get_phy_by_phandle(…,"usb-phy",0)` (`ehci-s5p.c:372`,
`ohci-exynos.c:333`), `usbphy-sys` via `of_get_child_by_name(…,"usbphy-sys")`
(`phy-samsung-usb.c:39`), `ehci`/`ohci` via `of_parse_phandle`
(`exynos-usb-switch.c:438,461`). All three j7elte board DTs (rev00, rev04,
rev06) include `exynos7580.dtsi` and add no USB overrides.

## Residual risks / tests

- No build was run (3.10 downstream tree vs. modern host GCC). Symbol and DT
  checks are static; runtime behaviour of the 3.10.61→3.10.108 delta is not
  exercised.
- `exynos-usb-switch` parses optional `samsung,id-gpio`, `samsung,bsess-gpio`,
  `samsung,vbus-gpio` and `uhost-vbus` regulator; the j7elte DT supplies none of
  these in either ROM or Nura, so the driver falls back to the "not available"
  paths in both (identical behaviour).
- On-device smoke tests: USB 2.0 host enumeration (mass storage / HID), OTG
  gadget mode via `samsung,exynos_udc` (adb/MTP/RNDIS), USB networking
  (wiki says Works), charger/OTG cable detection through the switch driver, and
  suspend/resume of EHCI/OHCI (runtime PM paths `exynos_ohci_runtime_*`,
  `ehci_s5p_*`).
