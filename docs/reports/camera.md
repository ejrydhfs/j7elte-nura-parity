Front camera reuses the 3L2 firmware (`fimc_is_ischain_loadfirm()` always uses

### The gap and the patch

`fimc_is_ischain_power()` calls `fimc_is_sec_run_fw_sel(dev, position)`
(`fimc-is-device-ischain.c:2612`) on every power-on while `CONFIG_USE_VENDER_FEATURE=y`.
For the rear sensor that reaches `fimc_is_sec_fw_sel_eeprom(dev, REAR, false)`
(`sec-define.c:3534`), which unconditionally opens
`/system/vendor/firmware/<load_fw_name>` to read the phone FW version (`:3620-3625`).
Any failure returned `-EIO`, and `fimc_is_ischain_power()` aborts with
`fimc_is_sec_run_fw_sel is fail` (`ischain.c:2613-2616`), so no camera stream can start on a
Linux filesystem layout. All other consumers already had a `request_firmware()` fallback.

`parity/patches/camera/0001-fimc-is2-fallback-to-request_firmware-for-fw-version-check.patch`
(in `drivers/media/platform/exynos/fimc-is2/vendor/fimc-is-sec-define.c` only):
when `filp_open()` of the vendor path fails, call
`request_firmware(&fw_blob, sysfs_finfo.load_fw_name, dev)`, take the 11-byte header version
from the tail of the blob (same offset as the file path: `size - 11`,
`FIMC_IS_HEADER_VER_SIZE` = 11, `sec-define.h:186`), `release_firmware()`, and continue with
`ret = 0`. No allocation, no path change for Android-style layouts (the vendor path is still
tried first). `git -C <tree> apply --check` → OK against baseline `b5e363a`; the tree was
reverted after patch generation and is clean.

Not patched (verified not built for this config / not applicable): companion and OIS loaders
(`CONFIG_COMPANION_USE`/`OIS_USE` = n, ROM has no symbols); the FROM (SPI ROM) variant
`fimc_is_sec_fw_sel()` at `sec-define.c:3769` is compiled out (no
`CONFIG_CAMERA_FROM_SUPPORT_REAR`); `mfc_fw.bin` belongs to the MFC driver and is out of
camera scope.

## Residual risks / required tests

1. **Packaging**: `device/archived/device-samsung-j7elte/APKBUILD` has no firmware handling
   (depends only on `linux-samsung-j7elte mkbootimg postmarketos-base`; `package()` copies
   just `deviceinfo`). The four files must be installed to `/lib/firmware/` by a firmware
   (sub)package or the initramfs; otherwise `request_firmware()` fails and
   `fimc_is_ischain_loadfirm()`/`loadfd()` still abort. Not edited here (shared pmaports file
   owned by the wifi agent).
2. **No cross build performed** (3.10 tree, no configured toolchain for it). The patch was
   verified only with `git apply --check`; it uses only APIs already included
   (`linux/firmware.h` via `fimc-is-sec-define.h:26`) and local variables, but a compile is
   still desirable.
3. **Clock table difference** (P1 caveat): the ROM clk driver exposes per-gate structs
   `aclk_fimc_isp_450`, `pclk_fimc_isp_225`, `aclk_mif_fimc_isp_333[_list]`,
   `aclk_mif_fimc_isp_pll[_list]`; Nura's `clk-exynos7580.c` models the ISP domain with
   `aclk_isp_1` (bit 26, parent `dout_aclk_fimc_isp_450`) and separate mux/div tables. The
   camera driver never requests those gate names, but if ISP power/clock gating misbehaves
   on hardware, compare the 7580 gate tables (bit positions) against the ROM driver.
4. **Userspace** (not patched, by design): the driver exposes V4L2/media-controller nodes
   (`fimc-is-video-*`, subdevs for 3AA/ISP/scaler/FD). Streaming requires a userspace client
   that speaks the Samsung IS ioctls and metadata layout (`include/fimc-is-metadata.h`,
   `fimc-is-param.h`, `V4L2_CID_IS_*`), i.e. an Android-camera-HAL-compatible stack or a
   dedicated V4L2 app; there is no libcamera pipeline handler for this block. Kernel parity
   does not provide a working camera UI on its own.
5. **Runtime checks**: after install and boot, `dmesg` should show
   `Camera: phone fw version: …`, `FW version : …`, `SETFILE version : …`,
   `Camera: the default FW were applied successfully` and
   `Camera: the default Setfile were applied successfully`; `media-ctl -p` should enumerate
   the ischain entities. Sensor probe/EEPROM read require the EEPROM i2c nodes (P2-verified)
   and the `VDDIO_1.8V_CAM/VT` regulators.
