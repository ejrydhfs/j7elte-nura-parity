## 3. RDS attempt: PREPARED, NOT SENT (exact bytes for resume)

Planned single pair (fc15-table.md RDS row: set_rds_mode = W1B(0x14,cfg,0) +
R(0x80,0,0xF0)):

- W1B(0x14, cfg=0x01, flags=0): payload bytes `14 10 01`, HCI frame
  `01 15 fc 03 14 10 01` (H4 01 + opcode fc15 LE + plen 03).
- R(0x80, r1=0, r2=0xF0): payload per read-arg rule = `[80, 0x11 | ...]`.
  NOTE: r2=0xF0 is the read LENGTH/flag field consumed by the stack-side
  helper (bta_fm_vnd_cmd_read), NOT an HCI-level arg byte — the on-wire read
  arg byte is derived from r1 only (r1=0 → arg 0x11; cf. R(0x0A,0,2) → tx
  `... 02 0a 19` where 0x19 = 0x11|0x08 length-class bit from the table's
  helper encoding). Exact R(0x80) wire bytes were staged in /tmp/probeAB.py
  as `01 15 fc 02 80 19`; FmLiveTune's quiet-line CC evidence + hci_raw
  framing confirm the form, but these bytes were NEVER transmitted — recheck
  arg encoding against fc15-table.md sec 0 before sending on resume.
- Expected result (per peer + §6 blocker): CC `04 0e 06 01 15 fc 00` +
  2-byte subcmd/arg echo, NO RDS payload bytes — record as dataless if so.
- Full probe script (/tmp/probeAB.py, host scratch, NOT repo) implements:

## 6. Flood-mitigation recipe (for the daemon; from live-fc15-log.txt §§4-6 +
##     probe-baseline.txt + this session's quiet-line confirmation)

- Kernel-side: setsockopt SOL_HCI/HCI_FILTER with type-mask accepting ONLY
  event 0x0E (Command Complete):
  `struct.pack('IIIH', 1<<0x0E, 1<<0x0E>>32, 0, 0)` — i.e. type_mask with bit
  0x0E set, event-mask words selecting 0x0E; exact layout: type_mask u32,
  event_mask[2] u32, opcode u16 (all-events = ~0,~0,~0,0 per baseline recipe).
- Userspace pattern per command: (a) set all-events filter + drain socket
  (nonblocking recv until EAGAIN/timeout, cap ~3000) to clear backlog;
  (b) set 0x0E-only filter + drain once more; (c) send H4 command
  `01 <opcode LE> <plen> <payload>`; (d) wait CC with short window (≤2.5 s),
  matching on opcode and IGNORING non-matching CCs (count as skipped);
  (e) set all-events filter for the post-command watch window (0.4–1.0 s)
  to census async vendor traffic (`04ff0108` vs any non-flood data).
- Defaults: CC window 2.5 s; drain cap 3000; presample 1 s; NEVER issue the
  W1B(0x4D,1,8) audio-path write except via explicit user action (it re-arms
  the persistent ~2.9k/s `04 ff 01 08` flood that drowns every CC window —
  disable leg does NOT stop it); after such a write, re-drain before every
  subsequent command; treat dataless 6-byte CCs (status + 2-byte echo, zero
  value bytes) as command-acceptance only, NOT signal confirmation.
- ALSA capture needs no HCI and is unaffected by the flood (peer FmAudioEv).
